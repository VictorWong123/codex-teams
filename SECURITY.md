# Security model and release review

Codex Teams is a single-user local service. Project/goal/member authentication provides logical separation, **not OS isolation** against the same operating-system user, a malicious extension or a model with filesystem access to that user's files. Codex sandboxes and managed restrictions provide the underlying execution controls; the orchestrator never promises stronger protection. Keep sensitive files out of writable workspaces and use restrictive Codex permissions. A model with same-user shell access is not treated as an untrusted OS principal.

The service binds 127.0.0.1, validates exact Host and Origin, rejects cross-site Fetch metadata, authenticates API requests, requires a custom CSRF header, limits JSON requests to 1MB and sets HTTP deadlines/CSP/nosniff/no-referrer/no-store. The dashboard renders untrusted content with textContent; no inline script, unsafe HTML rendering, token URL query or unauthenticated control endpoints exist. The credential URL fragment is cleared and tab session storage is cleared by Lock. HTTP is local-only; do not expose/forward the service port.

Master credentials are random, stored mode0600 under a private state directory and never passed to member MCP clients. Scoped bearer credentials bind project/goal/agent via HMAC; headers or model arguments cannot forge sender identity. All task/message/goal mutations enforce scope and terminal lifecycle. Members cannot use human controls, configuration or approvals. Before model dispatch, effective inherited MCP servers are disabled for that thread and the actual connected inventory must contain the complete scoped member tool set and no unexpected inherited tools. On-disk Codex configuration is preserved. Nested Codex agents are disabled so model work cannot escape orchestration accounting. Human client guards provide additional defense, but do not substitute for same-user isolation.

Codex0.163 app-server must report ChatGPT account authentication. API-key environment variables are removed from children; provider/model fallback is refused before turns. Authentication files/tokens are neither read nor copied. Raw app-server stderr is not logged. No automatic approvals, permission widening, separately billed API client, credit/reset consumption or external messages are used. Method-specific responses validate grants against requested permission subsets; unsupported methods are denied.

Events are registered before turn/start, buffered until its authoritative turn ID is known and bound to that ID thereafter. Stale completions/items cannot affect current turns; completed item IDs are deduplicated. Persisted dispatch intent and control-generation fences protect setup/control races. Known pre-turn cancellation restores only the exact undelivered queue entries; ambiguous work always requires history/effect review. Task-attempt evidence cannot be reused after correction. Positive test summaries and concrete captured source artifacts are required in addition to lead review; this cannot establish semantic correctness of arbitrary tests by itself.

Installer/uninstaller preflight both CLI aliases (`cteam` and compatible `codex-teams`) and owned-path/MCP collisions, preserve unrelated entries and back up existing Codex configuration. macOS service stop/start validates the canonical regular plist, owned marker, exact label, expected Node runtime/service script and loaded plist path, and rejects alternate executable keys before bootout/bootstrap/kickstart; it preserves the plist and refuses ambiguous/unrelated jobs. Command-selection tests are mocked and do not establish actual macOS operation. Uninstall removes either CLI link only when its target exactly matches this package, preserving unrelated files and links. Uninstall never purges state/worktrees. Package contents use a deliberate allowlist and portable paths. Distribution source files are readable/executable with conventional package modes; private runtime state is not made public. SDK1.32.1 replaces vulnerable1.21.1. Release audit and negative tests, including real auth-free matching-protocol MCP isolation, are recorded in `VALIDATION.md`.

If you find a vulnerability, report it privately to the repository owner through GitHub's available private reporting/contact mechanism. Do not publish tokens or user conversation data in issues. This release has no hosted service or shared consumer credentials.
